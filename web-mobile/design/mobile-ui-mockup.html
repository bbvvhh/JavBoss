JavBoss 移动端 · UI 设计稿

新增独立工程 web-mobile/，不改动现有 web/ PC 端。手机访问自动切换；电脑访问保持原样。以下为 390×844（iPhone 14 逻辑分辨率）高保真稿。

① 视频列表是主角 默认大图单列（标题完整 + 演员 + 标签），顶部仅 84px 双层精简控制栏，可切标准 2 列 / 紧凑 3 列。
② 搜索按需展开 默认只是一个放大镜图标；点开后顶栏变形为输入框，实时搜索结果。
③ 设置只留入口，功能不缩水 首屏完全不占位，顶栏右上角齿轮进入「我的」；14 个入口覆盖 PC 端全部设置能力。
④ 复杂筛选下沉到抽屉 排序 / 标签 / 刮削状态 / 时长全部放进底部抽屉，首屏只留常用快捷 chips。
⑤ 绝不删除视频文件 删除 / 覆盖 / 目录整理一律封禁；仅保留「重命名文件」且带三重防护。

安全红线：移动端永不删除、永不覆盖任何视频文件

已核实：现有 DELETE /videos/{id}/locations/{locationId} 会调用 util.MoveFileToTrash，而该函数在 Linux / macOS 上就是 os.Remove，即永久删除文件； POST /directories/{id}/process（目录整理）内部也含 os.Remove / os.Rename。

  • 永久封禁：删除文件（DELETE .../locations/...）、目录整理（ /directories/{id}/process）、/videos/open、/videos/reveal
  • 允许但加防护：重命名文件（PATCH .../locations/...）—— 只改名、不删除，且后端已自带三重防护（见 DESIGN.md §0.5）
  • 允许：全部只读操作；只写数据库的元数据（标签、收藏、刮削信息）
  • 允许：只写 JavBoss 自己 data/ 目录的操作（缩略图、截图、封面、缓存）
  • 替代方案：需要「清理列表」时用 从媒体库移除（文件保留）——只隐藏数据库记录，磁盘文件原封不动，且下次扫描会自动恢复

  • 重命名会写真实文件，所以做成带预览的确认页，不会一键生效

  • 后端三重防护：目标已存在 409；路径已在库 409；DB 失败自动改回原名
  • 大小写改名会被 NOCASE 校验拒绝，UI 直接说明原因
